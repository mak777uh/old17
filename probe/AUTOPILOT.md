Роль: внешний аналитик задачи `S8-data-questions` — искать в литературной карте несходимости данных и слать вопросы с числами. Формат вопросов, шкала и классы — ниже; полный протокол у локального агента probe (INSTRUCTION.md).

- **mak777uh/old17** — служебный (только чтение для облака): `probe/AUTOPILOT.md` (этот файл), `probe/STATE.md` (счёт, приоритеты, отложенное), `probe/cloud-notes.md`.

## Шаги аналитика (каждый пульс)

1. Прочитать `probe/AUTOPILOT.md` и `probe/STATE.md` (old17) для контекста и приоритетов.
2. Прочитать `.coord/standing/S8-data-questions.md` (marfagenez) — что искать и в каком порядке.
3. Выбрать одну ограниченную область проверки: один-два chunk или одну группу id. Весь корпус за пульс не нужен; если chunk-файлов ещё нет — см. «Диагностика».
4. Искать несходимости по классам standing. Числа — только из текста прочитанных ячеек. Интернет для чисел и фактов запрещён.
5. Дедуп: `search_issues` по `repo:mak777uh/marfagenez label:probe-round` (и старым `repo:mak777uh/old17 label:probe-round`) — не повторять (kind + atoms) и дословный текст вопроса.
6. Отправить ОДИН issue в **marfagenez**, label `probe-round`, тело строго:

```
PROCESSED: <что прочитал: chunk-файлы/группы id>
QUESTIONS:
<JSONL-строки вопросов по формату ниже, максимум 6, или none>
SEEN-ADD:
<JSON-массив пар [kind, atoms], или none>
```

Закрывать issue не нужно. Холостой пульс (вопросов нет) — issue НЕ создавать, ответить одной строкой.

## Формат вопроса (одна JSON-строка)

- `question` ≥20 символов, по-русски, с конкретикой и числами.
- `atoms` — существующие id ячеек.
- `kind`: `units` | `numbers` | `order` | `gap-as-support` | `no-locator`.
- `numbers` — ≥2, каждое буквально встречается в тексте своих ячеек.
- `verifiable` — обязательное: как проверить (честный recalc).
- Для `units` и `order` обязателен `recalc` — пересчёт, который сходится/не сходится.
- ≤6 вопросов за пульс (правило main: каждый разбирается руками; «3 точных лучше 20 шумных»).

## Приоритет поиска

1. Внутри ОДНОЙ ячейки (ценнее всего).
2. Между ячейками одной работы.
3. Между разными работами.

## Диагностика

- Нет `literature/map/atoms-chunks/` (или пусто): создать диагностический issue label `probe-round` с первой строкой `CORPUS MISSING` — локальная сторона передаст main, что нужно прогнать `split_atoms_for_github.sh`.
- Файл не читается (>1 МБ, 403, 404): не падать — использовать `search_code` по `repo:mak777uh/marfagenez` для точечных запросов по id из edges.jsonl, и упомянуть проблему в PROCESSED (issue только если есть вопросы; диагностика — единственное исключение, когда issue создают без вопросов).
- Функция недоступна напрямую: найти через `search_tool_functions` (best_match → details).
